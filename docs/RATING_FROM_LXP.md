# Рейтинг: годовая событийная модель

Сервис: `apps.progress.services.lxp_rating_from_snapshot.apply_rating_from_lxp_snapshot`.

## Главный принцип

Рейтинг **копится за учебный год** и меняется только на **событиях**.

Раньше каждый ночной снимок заново оценивал текущее состояние: +20 за каждую
закрытую тему и −20 за каждую открытую. Одно и то же положение дел
пересчитывалось ежедневно, поэтому:

| | старая модель | новая модель |
|---|---|---|
| 1 курс, 2 закрыто / 12 открыто | 300 → 160 за 10 дней | без изменений, пока не вышел срок тем |
| 3 курс, всё закрыто | 300 → 1000 за 10 дней | +бюджет за реально закрытые темы |
| открытая тема, срок не вышел | −20 каждый день | 0 |
| одна и та же закрытая тема | +20 каждый день | +цена темы один раз |

## Что начисляется

| Событие | Начисление | Повторяемость |
|---|---|---|
| Тема перешла из открытой в закрытую | `+CT_YEAR_BUDGET / ожидаемое число тем курса` | один раз на тему |
| Тема открыта дольше `TOPIC_STALE_DAYS` (30 дней) | `STALE_PENALTY_PER_TOPIC` (−20) | один раз на тему |
| Все темы закрыты | `CT_ALL_CLOSED_BONUS` (+30) | не чаще раза в 30 дней, один раз за учебный год |
| Открытая тема, срок не вышел | 0 | — |

Первый снимок для студента **ничего не начисляет**: он фиксирует исходное
состояние (`LXPTopicState.baseline_done`). Иначе при подключении системы
старшие курсы получили бы рейтинг задним числом за всё, что закрыли раньше.

## Честность между курсами

Курс с 60 темами в году и курс с 30 темами при одинаковой цене темы имели бы
вдвое разный потолок. Поэтому цена темы нормируется:

```
цена темы = CT_YEAR_BUDGET / ожидаемое число тем курса
```

Ожидаемое число тем не задаётся руками: `CourseTopicNorm` хранит наблюдаемый
по курсу максимум объёма тем на студента и только растёт по мере появления
новых дисциплин. Цена ограничена рамками `CT_POINTS_MIN` … `CT_POINTS_MAX`,
чтобы вырожденная когорта (одна тема на курс) не давала +400 за штуку.

Итог: закрывший всю программу года студент любого курса получает примерно
`CT_YEAR_BUDGET` баллов, а не «сколько успел набежать по объёму программы».

> Побочный эффект: в начале года наблюдаемый объём меньше итогового, поэтому
> ранние темы стоят чуть дороже поздних. Это осознанный компромисс — иначе
> пришлось бы вручную заводить план по каждому курсу.

## Блокировка при просроченных КТ

`unclosed_ct_count` теперь считает **просроченные** темы (открытые дольше 30
дней), а не любые открытые. Порог `STALE_BLOCK_THRESHOLD` (2) запрещает рост
рейтинга выше жёлтой зоны (399), но **не срезает** уже накопленное за год:
раньше две зависшие темы обнуляли вклад всех прошлых месяцев.

Блокировка распространяется и на награды за квесты, значки, социальные
механики и «Движ» — см. `apps.operations.services.anticheat`.

## Посещаемость

Флаг `hasAttendance` из `searchStudents` приходит **без привязки к дате** —
это свойство студента за всё время обучения. На нём нельзя строить ни дневной
штраф, ни серию. Поэтому:

* штраф за пропуск и бонус «неделя без пропусков» из снимка LXP **убраны**;
* посещаемость в рейтинге считается по проходам турникета (`ExternalEvent`
  источника `hik`) — см. `apps.progress.services.strike_bonuses`;
* день учитывается, только если по нему **есть данные Hik** и у отряда в этот
  день недели **есть пары**: выходные, каникулы и сбои выгрузки не рвут серию;
* квест по LXP переведён на **процент посещаемости по дисциплинам**
  (`by_discipline.visited/total`), порог 80%, период — неделя.

## Опоры (еженедельно, `recalculate_pillars_weekly`)

| Опора | Источник | Формула |
|-------|----------|---------|
| `power` (Мощность) | `grades.data[lxp_user_id]` | Средний `disciplineGrade` → шкала 1–20 |
| `rhythm` (Ритм) | `attendance.by_discipline` | Средний % посещаемости → шкала 1–20 |

## Годовой цикл

```bash
docker compose exec web python manage.py start_rating_year --dry-run
docker compose exec web python manage.py start_rating_year
```

Команда возвращает всех агентов на `DEFAULT_RATING_START` (300), обнуляет
счётчик просроченных КТ и очищает состояние тем (программа нового года —
новые темы). Итог прошлого года остаётся в `RatingLog` записью
`year_start:<год>`.

Границы года — `ACADEMIC_YEAR_START_MONTH/DAY` (по умолчанию 1 сентября).

## Настройка

Всё в `hero_path/settings/rating_coefficients.py`, блок `RATING_YEAR`.
Через окружение переопределяются: `CT_YEAR_BUDGET`, `TOPIC_STALE_DAYS`,
`STALE_PENALTY_PER_TOPIC`, `STALE_BLOCK_THRESHOLD`.

## Ограничения

- **У LXP нет поля дедлайна темы.** «Просрочка» выводится из наблюдений: тема
  висит открытой дольше `TOPIC_STALE_DAYS`. Отсчёт идёт с первого снимка, где
  тема увидена открытой, — то есть для тем, существовавших до подключения
  системы, срок считается от даты подключения.
- **Ключ темы** — `<дисциплина>:<id темы>`. Если LXP не отдаёт `topic.id`,
  ключом становится название, а в крайнем случае порядковый номер: при смене
  порядка тем в дисциплине состояние по ним сбросится.
- **Снимок обходит не больше `LXP_SNAPSHOT_MAX_GROUPS` (50) групп.** Если
  групп в колледже больше, часть курсов в снимок не попадёт и рейтинг по КТ
  им начисляться не будет. Следите за `meta.partial` и поднимайте лимит.
- Интерпретация статусов тем — эвристика по подстрокам
  (`apps.progress.services.ct_status`). Единая для рейтинга и для квестов.

## Журнал

Каждое изменение — запись `RatingLog`:

| `source_id` | Что это |
|---|---|
| `2026-10-01` (дата) | основная дельта за снимок этого дня |
| `ct_all_closed:2026/2027` | маркер бонуса «все КТ закрыты» за учебный год |
| `attendance_streak:7:<начало серии>` | бонус за серию без пропусков |
| `late_streak:14:<начало серии>` | бонус за серию без опозданий |
| `drive:OLYMPIAD_WIN:2026-10-01` | начисление за «Движ» |
| `year_start:2026/2027` | сброс на старте учебного года |
